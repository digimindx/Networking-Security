# نموذج أمان Azure (Azure Security Model)
**إطار الدورة:** Phase 3 – Microsoft Azure Fundamentals (Weeks 13–16)
**المodule:** AZ-900 - Module 4

---

## مقدمة
تعتبر الأمان (Security) الركيزة الأساسية لأي بيئة سحابية. تقدم Microsoft منصة Azure بمجموعة واسعة من الخدمات والميزات المصممة لحماية بيانات العملاء وتطبيقاتهم. في هذا الجزء من الدورة، سنتناول المبادئ الأساسية لنموذج أمان Azure وكيفية تطبيقها.

---

## 1. نموذج المسؤولية المشتركة (Shared Responsibility Model)

يعد فهم نموذج المسؤولية المشتركة (Shared Responsibility Model) هو أهم مفهوم في أمان السحابة. يحدد هذا النموذج المسؤوليات المشتركة بين مزود الخدمة (Microsoft) والعميل (Customer).

*   **مسؤولية Microsoft (Security *of* the Cloud):**
    *   تقوم Microsoft بحماية البنية التحتية التي تعمل عليها جميع الخدمات في Azure.
    *   تشمل هذه المسؤولية حماية الأجهزة، والشبكات، ومراكز البيانات (Datacenters)، والتطبيقات السحابية الأساسية.
    *   الهدف هو ضمان سلامة النظام الأساسي (Underlying Infrastructure).

*   **مسؤولية العميل (Security *in* the Cloud):**
    *   يتحمل العميل مسؤولية أمان وإدارة ما يقوم بوضعه داخل السحابة.
    *   تشمل هذه المسؤولية: إدارة نظام التشغيل (Operating System)، والتطبيقات المثبتة، وإعدادات جدار الحماية (Firewall)، وإدارة الهوية والصلاحيات (Identity and Access Management)، وتشفير البيانات.

**مثال توضيحي:**
إذا قمت بتشغيل (Virtual Machine)، فإن Microsoft مسؤولة عن أمان الخادم المادي الذي يعمل عليه هذا الجهاز الافتراضي، بينما أنت مسؤول عن تحديث نظام التشغيل (OS Patches) وتثبيت برامج الحماية داخل الجهاز الافتراضي.

---

## 2. الأمان الجسدي (Physical Security)

تستثمر Microsoft مليارات الدولات سنوياً في أمان مراكز البيانات (Datacenters) الخاصة بها.

*   **معايير الأمان:** تخضع مراكز بيانات Azure لمعايير دولية صارمة مثل (ISO 27001) و (SOC 1, 2, 3).
*   **إجراءات الدخول:** الدخول إلى مراكز البيانات يتطلب موافقات متعددة، واستخدام الماسح الضوئي للبصمات (Fingerprint scanners)، وكاميرات المراقبة (CCTV)، وحراس أمن يعملون على مدار الساعة (24/7).
*   **الشفافية:** يمكن للعملاء الاطلاع على تقارير التدقيق (Audit Reports) عبر موقع (Azure Trust Center).

---

## 3. أمان الشبكة (Network Security)

توفر Azure مجموعة من الخدمات لحماية البنية التحتية للشبكة ومنع الهجمات الإلكترونية.

*   **حماية DDoS (Azure DDoS Protection):**
    *   خدمة مصممة لحماية تطبيقات الشبكة من هجمات حجب الخدمة الموزعة (Distributed Denial-of-Service attacks).
    *   تقوم بفلترة حركة المرور الضارة تلقائياً قبل وصولها إلى الموارد.

*   **جدار حماية Azure (Azure Firewall):**
    *   خدمة إدارة الشبكة السحابية (Managed Cloud Security Service).
    *   توفر حماية شاملة من الجيل التالي (Next-generation firewall) وإدارة حركة المرور بين الإنترنت والبنية التحتية السحابية.

*   **مجموعات أمان الشبكة (Network Security Groups - NSG):**
    *   تعمل كـ (Firewall) بسيط على مستوى الشبكة.
    *   تتحكم في حركة المرور الواردة (Inbound) والصادرة (Outbound) للموارد السحابية بناءً على قواعد محددة (مثل السماح أو منع بورت معين).

*   **الربط الخاص (Private Link):**
    *   يتيح الوصول إلى الخدمات السحابية (مثل Azure SQL) عبر عنوان IP خاص داخل الشبكة الافتراضية (VNet)، مما يقلل من التعرض للواجهة العامة للإنترنت (Public Internet).

---

## 4. إدارة الهوية والوصول (Identity and Access Management - IAM)

يعتبر الهوية (Identity) هي حدود الحماية الجديدة في السحابة.

*   **Microsoft Entra ID (سابقاً Azure Active Directory):**
    *   هو نظام إدارة هويات ومؤسسي (Identity and Access Management service).
    *   يستخدم للمصادقة (Authentication) والتفويض (Authorization) للمستخدمين والتطبيقات.

*   **التحكم في الوصول القائم على الأدوار (Role-Based Access Control - RBAC):**
    *   نظام يمنح المستخدمين صلاحيات محددة بناءً على أدوارهم في المؤسسة.
    *   **أشهر الأدوار:**
        *   (Owner): صلاحيات كاملة بما في ذلك إدارة الصلاحيات.
        *   (Contributor): صلاحيات كاملة لإدارة الموارد ولكن لا يمكنه إعطاء صلاحيات للآخرين.
        *   (Reader): صلاحية عرض فقط دون تعديل.

*   **المصادقة متعددة العوامل (Multi-Factor Authentication - MFA):**
    *   تتطلب من المستخدم تقديم إثباتين أو أكثر للهوية (مثال: كلمة المرور + رمز يتم إرساله للهاتف).
    *   تعتبر ضرورية جداً لمنع سرقة الحسابات.

---

## 5. حماية البيانات (Data Protection)

توفر Azure أدوات لتشفير البيانات سواء كانت مخزنة أو قيد النقل.

*   **التشفير (Encryption):**
    *   **التشفير أثناء النقل (Encryption in Transit):** حماية البيانات أثناء انتقالها بين العميل والسحابة (عبر بروتوكولات SSL/TLS).
    *   **التشفير أثناء التخزين (Encryption at Rest):** حماية البيانات المخزنة في الأقراص أو قواعد البيانات.

*   **مفتاح الخزانة (Key Vault):**
    *   خدمة سحابية آمنة لتخزين المفاتيح السرية (Secrets)، ومفاتيح التشفير (Keys)، وشهادات (Certificates).
    *   يساعد في الحفاظ على التحكم في المفاتيح الخاصة بالتشفير.

*   **أنواع مفاتيح التشفير:**
    *   (Microsoft-managed keys): تقوم Microsoft بإدارة المفاتيح تلقائياً (الافتراضي).
    *   (Customer-managed keys): يقوم العميل بإنشاء وإدارة مفاتيح التشفير الخاصة به لزيادة التحكم.

## 6. الامتثال والحوكمة (Compliance and Governance)

*   **سياسة Azure (Azure Policy):**
    *   خدمة تتيح لك إنشاء وتنفيذ سياسات (Policies) على مستوى المؤسسة.
    *   مثال: منع إنشاء موارد في مناطق جغرافية محددة، أو منع إنشاء حسابات تخزين عامة (Public Storage Accounts).

*   **مدير الامتثال (Compliance Manager):**
    *   أداة تساعد في تتبع حالة الامتثال (Compliance Score) لمؤسستك ضد المعايير التنظيمية (مثل GDPR أو HIPAA).
    *   تقدم نصائح لتحسين درجة الامتثال.

---

## ملخص النقاط الرئيسية (Summary)

1.  **نموذج المسؤولية المشتركة:** Microsoft تحمي السحابة، العميل يحمي ما بداخلها.
2.  **الهوية:** استخدام (Microsoft Entra ID) و (RBAC) و (MFA) هو أساس الحماية.
3.  **الشبكة:** استخدام (NSG) و (Azure Firewall) للتحكم في حركة المرور.
4.  **البيانات:** تشفير البيانات (Encryption) هو ضروري دائماً.
5.  **الحوكمة:** استخدام (Azure Policy) لضمان توافق البيئة مع معايير الشركة.
