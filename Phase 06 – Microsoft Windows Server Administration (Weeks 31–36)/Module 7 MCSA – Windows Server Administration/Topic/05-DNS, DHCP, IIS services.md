# Module 7: DNS, DHCP, IIS Services
## القسم الخامس: خدمات الشبكة والاستضافة

### المقدمة
تعتبر هذه الخدمات الثلاث (DNS, DHCP, IIS) الركائز الأساسية لأي بنية تحتية للشبكات تعتمد على نظام Windows Server. في هذه الوحدة، سنستعرض المفاهيم، طرق التثبيت، الإعدادات المتقدمة، وأفضل الممارسات لضمان عمل هذه الخدمات بكفاءة وأمان.

---

## أولاً: خدمة DNS (Domain Name System)

### 1. المفهوم الأساسي
تقوم خدمة (Domain Name System) بترجمة الأسماء التي يسهل على الإنسان قراءتها إلى عناوين (IP Addresses) يفهمها الجهاز. بدون هذه الخدمة، سيتعين على المستخدمين تذكر عناوين IP الرقمية للوصول إلى المواقع.

### 2. أنواع المناطق (Zones)
عند تثبيت دور (DNS Server)، يجب إنشاء مناطق لتخزين السجلات:
*   **(Forward Lookup Zone)**: مسؤولة عن ترجمة الاسم إلى عنوان IP (مثال: تحويل `www.example.com` إلى `192.168.1.1`).
*   **(Reverse Lookup Zone)**: مسؤولة عن ترجمة عنوان IP إلى اسم (مهمة جداً لأغراض المراقبة وتحليل الأخطاء).

### 3. أنواع السجلات (Resource Records)
من أهم السجلات التي يجب معرفتها:
*   **(A Record)**: يربط اسم النطاق بعنوان IPv4.
*   **(AAAA Record)**: يربط اسم النطاق بعنوان IPv6.
*   **(CNAME)**: يستخدم لإنشاء اختصار أو Alias لاسم نطاق آخر.
*   **(MX Record)**: يحدد الخوادم المسؤولة عن البريد الإلكتروني.

### 4. التكامل مع Active Directory
في البيئات الحديثة، يتم تخزين بيانات الـ DNS عادة داخل (Active Directory-Integrated Zones). هذا يعني أن بيانات DNS يتم نسخها عبر جميع الموجهين (DNS Servers) في النطاق، مما يوفر:
*   **(Multi-master Replication)**: إمكانية التحديث من أي خادم.
*   أماناً عالياً عبر أذونات (Active Directory).
*   تقليل عبء الشبكة الناتج عن نسخ البيانات.

### 5. التحديثات الحديثة (أمن DNS)
في الإصدارات الحديثة (Server 2019/2022)، يركز المهندسون على تأمين الاتصال باستخدام:
*   **(DNS over HTTPS - DoH)**
*   **(DNS over TLS - DoT)**
وهذا يمنع التنصت على استعلامات البحث عن النطاقات.

## ثانياً: خدمة DHCP (Dynamic Host Configuration Protocol)

### 1. المفهوم الأساسي
تقوم هذه الخدمة بتوزيع عناوين IP، قناع الشبكة الفرعية (Subnet Mask)، البوابة الافتراضية (Default Gateway)، وخوادم الـ DNS تلقائياً للعملاء (Clients) دون تدخل يدوي.

### 2. المكونات الرئيسية
*   **(Scope)**: هو نطاق كامل من عناوين IP المتاحة للتوزيع.
*   **(Reservation)**: حجز عنوان IP ثابت لجهاز محدد (بناءً على الـ MAC Address)، بحيث يحصل هذا الجهاز دائماً على نفس العنوان.
*   **(Exclusion Range)**: نطاق من العناوين داخل الـ Scope يتم استبعاده من التوزيع (مثلاً للعناوين المحجوزة للطابعات أو الخوادم).

### 3. آلية العمل (DORA Process)
1.  **(Discover)**: يبحث العميل عن خادم DHCP.
2.  **(Offer)**: يقدم الخادم عنوان IP متاح.
3.  **(Request)**: يطلب العميل هذا العنوان.
4.  **(Acknowledge)**: يؤكد الخادم الطلب ويبدأ تشغيل (Lease).

### 4. التوافر العالي (High Availability)
طريقة (Split-Scope) القديمة لم تعد هي الموصى بها في البيئات الحديثة. الطريقة المعتمدة حالياً (أفضل ممارسة لعام 2024) هي:
*   **(DHCP Failover)**: ربط خادمين معاً (Peer-to-Peer).
    *   **(Stateful Mode)**: يحافظ على سجلات العقد (Lease Database) عند التوقف المفاجئ.
    *   **(Stateless Mode)**: يستخدم فقط لتوزيع العناوين دون مشاركة قاعدة البيانات (للتوزيع فقط).

## ثالثاً: خدمة IIS (Internet Information Services)

### 1. المفهوم الأساسي
هي خدمة ويب مقدمة من مايكروسوفت لاستضافة المواقع الإلكترونية وتطبيقات الويب. تعتمد على بروتوكول (HTTP/HTTPS).

### 2. مفاهيم إدارة التطبيقات (IIS Manager)
*   **(Web Site)**: هو الكيان الأعلى الذي يحتوي على التطبيقات.
*   **(Application)**: هو جزء من الموقع يحتوي على ملفات التطبيق (مثل ASP.NET أو PHP).
*   **(Virtual Directory)**: مسار يشير إلى مجلد خارج عن هيكل الموقع الافتراضي (مثلاً مجلد يحتوي على صور مشتركة).
*   **(Application Pool)**: مجموعة من العمليات التي تدير تطبيقاً أو مجموعة تطبيقات. الفصل بين التطبيقات في (App Pools) مختلفة يمنع توقف التطبيق A عند حدوث خطأ في التطبيق B.

### 3. إعدادات الربط (Bindings)
عند إنشاء موقع جديد، يجب تحديد:
*   **(IP Address)**: العنوان الذي سيعمل عليه الموقع.
*   **(Port)**: عادة 80 (HTTP) أو 443 (HTTPS).
*   **(Host Name)**: اسم النطاق (مثال: `www.example.com`).

### 4. الأمان والتحديثات الحديثة
*   **(SSL/TLS Configuration)**: يجب دائماً تثبيت شهادات (SSL Certificates) لتشفير الاتصال.
*   **(URL Rewrite Module)**: إضافة ضرورية لتحويل الروا (Redirect) وتحسين محركات البحث (SEO).
*   دعم **(ASP.NET Core)**: في الإصدارات الحديثة، يمكن استضافة تطبيقات .NET Core على IIS باستخدام (ASP.NET Core Hosting Bundle).

## رابعاً: التكامل بين الخدمات (Integration)

### 1. التسجيل الديناميكي (Dynamic Updates)
يمكن لخوادم DHCP تكوين خادم DNS تلقائياً:
*   عندما يحصل العميل على عنوان IP من DHCP، يقوم الـ DHCP Server بإرسال طلب للـ DNS Server لإنشاء سجل (A Record) لسجل العميل (A Record) وسجل (PTR Record) للعكس.
*   **ملاحظة:** يجب تفعيل خيار (Enable DNS dynamic updates) في إعدادات الـ Scope الخاص بالـ DHCP.

### 2. سيناريو عملي (Best Practice)
في بيئة عمل منظمة:
1.  يتم تثبيت دور (DHCP Server) وتوزيع العناوين.
2.  يتم تثبيت دور (DNS Server) وإنشاء (Forward Lookup Zone) من نوع (Active Directory-Integrated).
3.  يتم تثبيت دور (IIS) لإنشاء موقع ويب.
4.  يتم التأكد من أن الـ IIS يستخدم الـ DNS المحلي لحل أسماء الخوادم الأخرى (مثل خادم البريد أو قاعدة البيانات).

### ملخص الوحدة
لقد غطينا في هذه الوحدة الأساسيات التقنية لخدمات الاتصال والاستضافة. لضمان نجاح المشروع، يجب التركيز على:
1.  أمان الـ DNS عبر (DoH/DoT).
2.  التوافر العالي لـ DHCP عبر (DHCP Failover).
3.  عزل التطبيقات في IIS عبر (Application Pools) المختلفة.
