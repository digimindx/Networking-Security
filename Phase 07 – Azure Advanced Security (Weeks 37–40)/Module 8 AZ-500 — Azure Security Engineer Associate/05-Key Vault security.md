# محتوى تدريبي: أمن مخزن المفاتيح في Azure
**Module:** AZ-500 - Azure Security Engineer Associate
**Chapter:** 05-Key Vault security

## 1. مقدمة (Introduction)
يعتبر (Azure Key Vault) خدمة سحابية أساسية في بيئة الحوسبة السحابية، مصممة لحماية المفاتيح المشفرة (Cryptographic Keys) والأسرار (Secrets) والشهادات (Certificates) التي تستخدمها التطبيقات والخدمات. الهدف الرئيسي هو تجنب تخزين المعلومات الحساسة (Sensitive Data) في الكود المصدري أو ملفات الإعداد (Configuration Files).

## 2. أنواع الكائنات في Key Vault
يقوم (Azure Key Vault) بإدارة ثلاثة أنواع رئيسية من الكائنات:

*   **المفاتيح (Keys):** تستخدم للتشفير غير المتماثل (Asymmetric Encryption) أو التوقيع الرقمي. يمكن أن تكون المفاتيح مدعومة ببرنامج (Software-backed) أو بوحدة أمان صلبة (Hardware Security Module - HSM).
*   **الأسرار (Secrets):** أي بيانات تريد حمايتها، مثل كلمات المرور (Passwords)، وسلاسل الاتصال (Connection Strings)، ومفاتيح (API Keys).
*   **الشهادات (Certificates):** يتم إصدار الشهادات الرقمية وإدارتها. تدعم الخدمة تجديد الشهادات تلقائياً (Automatic Renewal).

## 3. التحكم في الوصول (Access Control) - تحديث 2026
في السنوات الأخيرة، تغير نموذج التحكم في الوصول بشكل جذري. يجب على مهندس الأمن التركيز على الآليات الحديثة وتجنب القديم.

### أ. التحكم في الوصول المستند إلى الدور (Role-Based Access Control - RBAC)
هذا هو النموذج الموصى به حالياً والأكثر أماناً.
*   **المبدأ:** يتم منح الأذونات بناءً على الأدوار (Roles) المضمنة في Azure.
*   **الأدوار الرئيسية:**
    *   (Key Vault Secrets User): يسمح بقراءة واسترجاع الأسرار.
    *   (Key Vault Crypto User): يسمح باستخدام المفاتيح للتشفير وفك التشفير ولكن لا يسمح بقراءة قيمة المفتاح نفسه.
    *   (Key Vault Certificates Officer): يسمح بإدارة الشهادات.
    *   (Key Vault Contributor): يمنح صلاحيات كاملة بما في ذلك إدارة المفاتيح والأسرار.
*   **الميزة:** يسمح بتحكم دقيق (Granular Control) على مستوى العمليات (Operations) وليس فقط على مستوى الموارد.

### ب. سياسات الوصول (Access Policies) - (Legacy/Deprecated)
*   هذا هو النموذج القديم.
*   **الحالة:** تم إيقاف استخدامه رسمياً لإنشاء مستودعات مفاتيح جديدة. يجب عدم استخدامه في البيئات الجديدة.
*   **المشكلة:** يمنح الصلاحيات على مستوى المستودع بالكامل (All or Nothing)، مما يجعل من الصعب تطبيق مبدأ "أقل امتياز" (Least Privilege) بدقة.

## 4. الشبكات والاتصال (Networking and Connectivity)
يجب عزل (Azure Key Vault) عن الوصول العام قدر الإمكان.

*   **النطاق العام (Public Access):** يسمح بالوصول عبر الإنترنت العام. يُنصح بشدة بتعطيله في البيئات الإنتاجية.
*   **النقطة النهائية الخاصة (Private Endpoint):**
    *   يسمح بالاتصال بـ (Azure Key Vault) عبر الشبكة الخاصة الافتراضية (VNet).
    *   يستخدم (Private Link) لتأمين الاتصال دون الحاجة إلى (Public IP).
    *   يمنع تسرب البيانات عبر الشبكة العامة.
*   **جدار الحماية (Firewall):** يسمح بتحديد عناوين IP المسموح لها بالاتصال بالمستودع (يستخدم عادةً مع النطاق العام إذا كان ضرورياً).

## 5. استعادة الكوارث والحماية (Disaster Recovery & Protection)
لضمان استمرارية الأعمال وحماية البيانات من الحذف العرضي أو الخبيث:

*   **الحذف الناعم (Soft Delete):**
    *   ميزة مفعّلة افتراضياً.
    *   عند حذف كائن (Key/Secret/Certificate)، يتم الاحتفاظ بنسخة احتياطية لمدة 90 يوماً.
    *   يسمح باستعادة الكائن قبل طرده نهائياً.
*   **حماية الطرد النهائي (Purge Protection):**
    *   تمنع حتى المشرفين (Admins) من حذف الكائن نهائياً (Purge) قبل انتهاء فترة الـ 90 يوماً.
    *   ضرورية لمنع الهجمات التي تهدف لحذف البيانات الحساسة نهائياً.
*   **التكرار الإقليمي (Regional Redundancy):**
    *   ينسخ البيانات تلقائياً عبر مناطق جغرافية داخل المنطقة (Region) نفسها لضمان التوفر العالي.

## 6. ميزات متقدمة (Advanced Features)

### أ. مدير المفاتيح المميز (Managed HSM)
*   مورد (Resource) منفصل عن (Azure Key Vault) التقليدي.
*   يوفر مستويات أمان عالية جداً (FIPS 140-2 Level 3).
*   مناسب للبيانات شديدة الحساسية التي تتطلب أن تكون المفاتيح داخل عتاد مخصص (Dedicated Hardware) وليس مجزأة (Virtualized).

### ب. حسابات التخزين المدارة (Managed Storage Accounts)
*   يسمح لـ (Azure Key Vault) بإدارة مفاتيح حساب التخزين (Storage Account Keys) تلقائياً.
*   ميزة **تدوير المفاتيح تلقائياً (Auto-Rotation):** يقوم بتغيير مفاتيح التخزين بشكل دوري لتعزيز الأمان دون تدخل بشري.

### ج. شهادات Key Vault المدارة (Key Vault Managed Certificates)
*   مورد منفصل لإدارة دورة حياة الشهادات (إصدار، تجديد، نشر).
*   يدعم التكامل مع (Azure App Service) و (Azure Front Door) لنشر الشهادات تلقائياً.

## 7. أفضل الممارسات الأمنية (Security Best Practices)

1.  **استخدام RBAC دائماً:** لا تعتمد على سياسات الوصول القديمة (Access Policies).
2.  **تطبيق مبدأ أقل امتياز:** امنح المستخدمين فقط الصلاحيات التي يحتاجونها (مثلاً: (Key Vault Secrets Reader) بدلاً من (Contributor)).
3.  **استخدام Private Link:** تأكد من أن التطبيقات تتصل بـ (Key Vault) عبر (Private Endpoint) داخل (VNet).
4.  **تمكين المراقبة (Monitoring):**
    *   استخدم (Azure Monitor) و (Diagnostic Settings) لتسجيل كافة العمليات (Audit Logs).
    *   راقب أي محاولات وصول غير مصرح بها.
5.  **تفعيل Purge Protection:** لضمان عدم إمكانية حذف البيانات الحساسة نهائياً بشكل عشوائي.
6.  **استخدام Managed Identities:** عند ربط التطبيقات بـ (Key Vault)، استخدم (Managed Identities) لتجنب تخزين (Client ID) و (Secret) للتطبيق في الكود.
