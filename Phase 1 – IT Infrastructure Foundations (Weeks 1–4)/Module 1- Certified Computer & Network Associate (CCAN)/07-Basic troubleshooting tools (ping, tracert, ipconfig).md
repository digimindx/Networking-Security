# أساسيات استكشاف الأخطاء وإصلاحها في الشبكات

عند مواجهة مشاكل في الشبكة (Network Issues)، فإن الخطوة الأولى هي تشخيص المشكلة بدقة قبل محاولة حلها. يعتمد مسؤولو الشبكات على أدوات سطر الأوامر (Command Line Tools) المدمجة في أنظمة التشغيل، وتحديداً نظام ويندوز (Windows)، لفحص الاتصال، وتأكيد الوصول، وتتبع مسار الحزم (Packets).

سوف يغطي هذا التدريب ثلاثة أدوات حيوية:
1.  **ipconfig**: لعرض وتعديل إعدادات الشبكة.
2.  **ping**: لاختبار الاتصال (Connectivity).
3.  **tracert**: لتتبع المسار (Path Trace).

---

### أداة (ipconfig)
تُستخدم هذه الأداة لعرض جميع إعدادات الشبكة (Network Configuration) الحالية لجهاز الكمبيوتر.

#### 1. عرض الإعدادات الأساسية
لرؤية معلومات سريعة مثل عنوان IP (IP Address) وقناع الشبكة الفرعية (Subnet Mask) وجateway الافتراضي (Default Gateway)، اكتب في موجه الأوامر (Command Prompt):
`ipconfig`

#### 2. عرض التفاصيل الكاملة
لرؤية معلومات مفصلة جداً تشمل عنوان الـ MAC (Physical Address)، إعدادات الـ DHCP، وخوادم الـ DNS، استخدم الأمر:
`ipconfig /all`

#### 3. الأوامر المساعدة (Useful Flags)
*   **إفراغ ذاكرة التخزين المؤقت لـ DNS (Clear DNS Cache):**
    أحياناً يتسبب الـ DNS القديم في مشاكل في تصفح المواقع. لتفريغ الذاكرة، اكتب:
    `ipconfig /flushdns`
*   **إصدار عنوان IP (Release IP Address):**
    يقوم بإزالة عنوان IP الحالي من الجهاز (يفصلك عن الشبكة مؤقتاً).
    `ipconfig /release`
*   **الحصول على عنوان IP جديد (Renew IP Address):**
    يطلب من السيرفر (DHCP Server) إعطاء جهازك عنوان IP جديد.
    `ipconfig /renew`

جدول شرح الأمر بالكامل:

| القسم / الفئة       | الشرح                                                                                                                                       |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------ |
| **الغرض من الأمر**  | أداة سطر أوامر تُستخدم لعرض وتعديل إعدادات الشبكة (IP Address, Subnet Mask, Default Gateway) للواجهات المتصلة ببروتوكول TCP/IP.             |
| **الوضع الافتراضي** | عند تشغيل الأمر بدون أي خيارات، يقوم بعرض **عنوان IP، قناع الشبكة الفرعية (Subnet Mask)، وبوابة الافتراض (Default Gateway)** لكل واجهة فقط. |

### الخيارات (Options) المتاحة

| الخيار (Switch) | الوصف والوظيفة |
| :--- | :--- |
| **`/?`** | عرض رسالة المساعدة (هذا النص) لتوضيح كيفية استخدام الأمر. |
| **`/all`** | عرض **جميع** معلومات التكوين الكاملة للواجهات (تفاصيل أكثر شمولاً من الوضع الافتراضي). |
| **`/allcompartments`** | عرض معلومات عن جميع "الأقسام" (Compartments) الشبكية (مفيد في بيئات العزل الافتراضي). يمكن دمجه مع `/all` للمزيد من التفاصيل. |
| **`/release [adapter]`** | **إلغاء** تأجير عنوان IPv4 للواجهة المحددة. (إذا لم تُحدد واجهة، سيتم إلغاء تأجير جميع الواجهات). |
| **`/release6 [adapter]`** | **إلغاء** تأجير عنوان IPv6 للواجهة المحددة. |
| **`/renew [adapter]`** | **تجديد** تأجير عنوان IPv4 للواجهة المحددة (الحصول على عنوان IP جديد أو تمديد القديم). |
| **`/renew6 [adapter]`** | **تجديد** تأجير عنوان IPv6 للواجهة المحددة. |
| **`/flushdns`** | مسح (Purge) ذاكرة التخزين المؤقت (Cache) لمحلل أسماء DNS (DNS Resolver Cache). |
| **`/displaydns`** | عرض محتويات ذاكرة التخزين المؤقت لمحلل أسماء DNS. |
| **`/registerdns`** | تحديث جميع تأجير DHCP وإعادة تسجيل أسماء DNS (Refreshes all DHCP leases and re-registers DNS names). |
| **`/showclassid adapter`** | عرض جميع معرفات فئة DHCP (DHCP Class IDs) المسموح بها للواجهة المحددة. |
| **`/setclassid adapter [classid]`** | تعديل (تعريف) معرف فئة DHCP (DHCP class id) للواجهة. <br> *ملاحظة: إذا لم يتم تحديد ClassId، سيتم إزالة المعرف الحالي.* |
| **`/showclassid6 adapter`** | عرض جميع معرفات فئة DHCP الخاصة بـ IPv6 للواجهة المحددة. |
| **`/setclassid6 adapter [classid]`** | تعديل معرف فئة DHCP الخاص بـ IPv6 للواجهة. <br> *ملاحظة: إذا لم يتم تحديد ClassId، سيتم إزالة المعرف الحالي.* |

### ملاحظات هامة

| الملاحظة | التفاصيل |
| :--- | :--- |
| **المتغير `adapter`** | يمثل اسم الاتصال (Connection name). |
| **الرموز العامة (Wildcards)** | في خانة الـ `adapter`، يمكن استخدام الرموز `*` (أي عدد من الأحرف) و `?` (حرف واحد) لتسهيل البحث. <br> *مثال:* `EL*` تعني أي اتصال يبدأ بحرف E ثم L. |
| **السلوك عند عدم تحديد الـ Adapter** | - في `/release` و `/renew`: إذا لم يُذكر اسم الواجهة، سيتم تنفيذ الأمر على **جميع** الواجهات المتصلة بـ TCP/IP.<br> - في `/setclassid` و `/setclassid6`: إذا لم يُذكر الـ ClassId، سيتم **حذف** المعرف الحالي. |

### أمثلة عملية (Examples)

| الأمر | النتيجة / الوظيفة |
| :--- | :--- |
| `ipconfig` | عرض المعلومات الأساسية (IP, Mask, Gateway). |
| `ipconfig /all` | عرض المعلومات التفصيلية الكاملة. |
| `ipconfig /renew` | تجديد عناوين IP لجميع الواجهات. |
| `ipconfig /renew EL*` | تجديد الاتصال الذي يبدأ اسمه بـ "EL" (مثلاً Ethernet LAN). |
| `ipconfig /release *Con*` | إلغاء تأجير جميع الاتصالات التي تحتوي في اسمها على "Con" (مثلاً Wired Ethernet Connection). |
| `ipconfig /allcompartments` | عرض معلومات جميع الأقسام الشبكية. |
| `ipconfig /allcompartments /all` | عرض معلومات تفصيلية لجميع الأقسام الشبكية. |

### أداة (ping)
تُستخدم هذه الأداة للتأكد من ما إذا كان الجهاز قادراً على التواصل مع جهاز آخر (Host) عبر الشبكة. تعتمد هذه الأداة على بروتوكول (ICMP).

#### 1. الاختبار الأساسي
للتحقق من الاتصال بجهاز معين (مثلاً Google):
`ping google.com`

**كيف تقرأ النتيجة:**
*   **Reply from ...**: يعني أن الاتصال ناجح.
*   **Request timed out**: يعني أن الحزمة (Packet) لم تصل أو لم يعد لها رد.
*   **Destination host unreachable**: يعني أن الجهاز لا يعرف كيفية الوصول للوجهة نهائياً (مشكلة في التوجيه Routing).

#### 2. اختبار الاتصال المستمر (Continuous Ping)
إذا كنت تريد مراقبة الاتصال لفترة طويلة دون توقف (للكشف عن التقطع)، استخدم المفتاح `-t`:
`ping google.com -t`
*(لإيقاف الاختبار اضغط `Ctrl + C`)*.

#### 3. تغيير حجم الحزمة (Packet Size)
إذا كنت تريد اختبار قدرة الشبكة على نقل بيانات كبيرة (مثل الألعاب أو الفيديو)، يمكنك زيادة حجم الحزمة الافتراضي باستخدام المفتاح `-l` (الحرف L):
`ping google.com -l 1000`
(هذا الأمر يرسل حزمة بحجم 1000 بايت).

#### 4. تحديد عدد المحاولات
بشكل افتراضي يرسل (ping) 4 محاولات. لتغيير العدد، استخدم المفتاح `-n`:
`ping google.com -n 10`
(يرسل 10 محاولات فقط).

شرح كامل للأمر
إليك جدول يشرح أمر `ping` بناءً على النص المقدم، مقسماً إلى الأقسام الرئيسية:

| القسم / الفئة | الشرح |
| :--- | :--- |
| **الغرض من الأمر** | أداة سطر أوامر تُستخدم لاختبار الاتصال بين جهازين عبر الشبكة (Protocol ICMP) من خلال إرسال حزم بيانات (Echo Requests) واستقبال ردود (Echo Replies). |
| **التركيب الأساسي** | `ping [الخيارات] اسم_المضيف` (حيث `target_name` هو عنوان IP أو اسم المضيف الذي تريد فحصه). |

### الخيارات (Options) المتاحة

| الخيار (Switch) | الوصف والوظيفة |
| :--- | :--- |
| **`-t`** | إرسال طلبات Ping **مستمرة** (Until stopped) حتى يتم إيقاف الأمر يدوياً.<br> *لرؤية الإحصائيات والاستمرار:* اضغط `Control-Break`.<br> *لإيقاف الأمر:* اضغط `Control-C`. |
| **`-a`** | حل (Resolve) عناوين IP إلى أسماء مضيفين (Hostnames) عند عرض النتائج. |
| **`-n count`** | تحديد **عدد** طلبات Echo Requests المراد إرسالها (يتم الإيقاف تلقائياً بعد هذا العدد). |
| **`-l size`** | تحديد **حجم** ذاكرة التخزين المؤقت (Buffer Size) للحزم المرسلة بالبايت (Bytes). |
| **`-f`** | تعيين علم "عدم التجزئة" (Don't Fragment flag) في الحزمة. <br> *(IPv4-only)*: يمنع الحزم من التجزئة إذا كانت أكبر من MTU الخاص بالمسار. |
| **`-i TTL`** | تحديد قيمة **Time To Live** للحزم. تتحكم في عدد القفزات (Hops) المسموح بها قبل إسقاط الحزمة. |
| **`-v TOS`** | تحديد نوع الخدمة (Type Of Service) في رأس الحزمة. <br> *(IPv4-only)*: **ملغي/غير فعال** (Deprecated) ولا يؤثر حالياً على حقول الخدمة في الرأس. |
| **`-r count`** | تسجيل مسار الحزمة (Record Route) لعدد القفزات المحدد.<br> *(IPv4-only)*: مفيد في تتبع المسار الذي سلكته الحزمة. |
| **`-s count`** | إضافة طابع زمني (Timestamp) لعدد القفزات المحدد.<br> *(IPv4-only)*: يعطي معلومات عن الوقت المستغرق في كل قفزة. |
| **`-j host-list`** | تحديد مسار مصدر "رخي" (Loose Source Route) عبر قائمة مضيفين محددة.<br> *(IPv4-only)*: تمر الحزم عبر هذه العقد بالترتيب، لكن يمكنها القفز بين العقد الأخرى. |
| **`-k host-list`** | تحديد مسار مصدر "صارم" (Strict Source Route) عبر قائمة مضيفين محددة.<br> *(IPv4-only)*: يجب أن تمر الحزمة عبر هذه العقد بالترتيب الدقيق ودون تجاوزها. |
| **`-w timeout`** | تحديد وقت الانتظار (بالمللي ثانية) لكل رد قبل اعتبار الطلب قد فشل (Timeout). |
| **`-R`** | استخدام رأس التوجيه (Routing Header) لاختبار المسار العكسي أيضاً.<br> *(IPv6-only)*: **ملغي/غير فعال** (Deprecated) حسب RFC 5095، وقد تقوم بعض الأنظمة بإسقاط الطلبات. |
| **`-S srcaddr`** | تحديد **عنوان المصدر** (Source IP Address) المراد استخدامه لإرسال الطلبات. |
| **`-c compartment`** | تحديد معرّف **القسم الشبكي** (Routing Compartment Identifier) لاستخدامه في العزل الافتراضي للشبكة. |
| **`-p`** | فحص عنوان مزود افتراضية Hyper-V Network Virtualization.<br> *(خاص ببيئات Hyper-V)*. |
| **`-4`** | **إجبار** استخدام بروتوكول **IPv4** فقط. |
| **`-6`** | **إجبار** استخدام بروتوكول **IPv6** فقط. |

### ملاحظات هامة

| الملاحظة | التفاصيل |
| :--- | :--- |
| **التوافق مع الإصدارات القديمة** | الخيارات التي تحمل علامة *(IPv4-only)* لا تعمل على بروتوكول IPv6 والعكس صحيح، إلا إذا تم إجبار البروتوكول عبر `-4` أو `-6`. |
| **الخيارات الملغية (Deprecated)** | الخيارات `-v` (في IPv4) و `-R` (في IPv6) تم إلغاؤها تقنياً ولا يُنصح باستخدامها لأنها قد لا تعمل بشكل صحيح أو قد تسبب مشاكل في بعض الأنظمة الحديثة. |
| **التحكم في الاستمرارية** | الخيار `-t` مفيد لمراقبة استقرار الاتصال على المدى الطويل (مثل اختبار انقطاع الإنترنت)، بينما الخيارات الأخرى (`-n`) مناسبة للاختبارات السريعة. |

### أمثلة عملية (Examples)

| الأمر                         | النتيجة / الوظيفة                                                                 |
| :---------------------------- | :-------------------------------------------------------------------------------- |
| `ping google.com`             | إرسال 4 طلبات Ping افتراضية إلى google.com وعرض النتيجة.                          |
| `ping -t 192.168.1.1`         | إرسال طلبات Ping مستمرة إلى هذا العنوان حتى تقوم بإيقافه بـ `Ctrl+C`.             |
| `ping -n 10 -l 1000 site.com` | إرسال 10 طلبات، كل منها بحجم 1000 بايت.                                           |
| `ping -4 -n 4 8.8.8.8`        | إجبار استخدام IPv4 وإرسال 4 طلبات فقط.                                            |
| `ping -w 2000 site.com`       | تعيين وقت الانتظار لكل رد إلى ثانيتين (2000 مللي ثانية) بدلاً من الوقت الافتراضي. |

### داة (tracert)
أداة (Trace Route) تستخدم لتتبع المسار الذي تسلكه الحزم (Packets) من جهازك إلى الوجهة النهائية. تساعد في معرفة أين يحدث التوقف أو التأخير.

#### 1. الاستخدام الأساسي
`tracert google.com`

**كيف تقرأ النتيجة:**
*   تظهر الأداة قائمة بعدد (Hops) أي عدد الموجهات (Routers) التي مرت بها البيانات.
*   في كل سطر يظهر الوقت (Time) المستغرق للوصول إلى ذلك الموجه بالمللي ثانية (ms).

#### 2. إخفاء أسماء النطاقات (Disable DNS Resolution)
أحياناً يستغرق الأمر وقتاً طويلاً لأن الأداة تحاول تحويل عنوان IP إلى اسم نطاق (Hostname). لتسريع العملية وإظهار العناوين فقط، استخدم المفتاح `-d`:
`tracert google.com -d`

#### 3. تفسير النجوم (Asterisks)
إذا رأيت `* * *` في سطر معين، فهذا يعني أن الموجه (Router) في تلك المرحلة لا يستجيب (Unresponsive) أو أنه قام بحظر استعلامات (ICMP). لا يعني ذلك بالضرورة توقف الشبكة، بل أن الموجه لا يرد على الاستعلامات.

#### 4. تحديد حد للمسار (Max Hops)
بشكل افتراضي يبحث عن 30 خطوة. لتقليل عدد الخطوات (مفيد إذا كنت تعرف أن المشكلة بعيدة)، استخدم المفتاح `-h`:
`tracert google.com -h 10`

شرح الأمر بالكامل

إليك جدول يشرح أمر `tracert` (Trace Route) بناءً على النص المقدم، مقسماً إلى الأقسام الرئيسية:

| القسم / الفئة | الشرح |
| :--- | :--- |
| **الغرض من الأمر** | أداة سطر أوامر تُستخدم لتحديد المسار الذي تسلكه الحزم للوصول إلى مضيف معين على الشبكة (Internet أو شبكة محلية)، وعرض عدد القفزات (Hops) والوقت المستغرق في كل قفزة. |
| **التركيب الأساسي** | `tracert [الخيارات] اسم_المضيف` (حيث `target_name` هو عنوان IP أو اسم المضيف المراد تتبع مساره). |

### الخيارات (Options) المتاحة

| الخيار (Switch) | الوصف والوظيفة |
| :--- | :--- |
| **`-d`** | **عدم حل** العناوين إلى أسماء مضيفين (Do not resolve addresses). <br> *الفائدة:* يجعل الأمر أسرع لأنه يتخطى مرحلة البحث عن أسماء السيرفرات الوسيطة. |
| **`-h maximum_hops`** | تحديد **الحد الأقصى** لعدد القفزات (Hops) التي سيقوم الأمر بفحصها للعثور على الهدف. <br> *القيمة الافتراضية* عادةً ما تكون 30 قفزة. |
| **`-j host-list`** | تحديد مسار مصدر "رخي" (Loose Source Route) عبر قائمة عناوين IP محددة.<br> *(IPv4-only)*: تجبر الحزم على المرور عبر هذه العقد بالترتيب المحدد. |
| **`-w timeout`** | تحديد **وقت الانتظار** (بالمللي ثانية) لكل رد من كل قفزة. <br> *القيمة الافتراضية* عادةً ما تكون 4000 مللي ثانية (4 ثوانٍ). إذا انتهى الوقت دون رد، تظهر علامة `*`. |
| **`-R`** | تتبع المسار ذهاباً وإياباً (Round-trip path). <br> *(IPv6-only)*: يعرض المسار العكسي أيضاً، لكن قد لا يدعمه جميع الأنظمة الحديثة. |
| **`-S srcaddr`** | تحديد **عنوان المصدر** (Source IP) المراد استخدامه لإرسال الطلبات.<br> *(IPv6-only)*: مفيد إذا كان لدى الجهاز أكثر من عنوان IPv6. |
| **`-4`** | **إجبار** استخدام بروتوكول **IPv4** فقط. |
| **`-6`** | **إجبار** استخدام بروتوكول **IPv6** فقط. |

### ملاحظات هامة

| الملاحظة | التفاصيل |
| :--- | :--- |
| **القيود البروتوكولية** | الخيار `-j` (Loose Source Route) يعمل فقط مع **IPv4**. الخيار `-S` و `-R` يعملان فقط مع **IPv6** (وفقاً لهذا النص المحدد). |
| **تفسير النجوم `*`** | إذا ظهر `*` في عمود الوقت، فهذا يعني أن القفزة لم ترد خلال وقت الـ `timeout` المحدد (سواء بسبب جدار ناري يمنع ICMP أو بطء الشبكة). |
| **الهدف من الأمر** | يستخدمه المهندسون لتشخيص مشاكل الشبكة، مثل معرفة أين يحدث الانقطاع أو التأخير في مسار الاتصال. |

### أمثلة عملية (Examples)

| الأمر | النتيجة / الوظيفة |
| :--- | :--- |
| `tracert google.com` | تتبع المسار الافتراضي إلى google.com باستخدام عدد القفزات الافتراضي. |
| `tracert -d 192.168.1.1` | تتبع المسار إلى هذا العنوان دون محاولة تحويل عناوين الـ IP إلى أسماء (أسرع). |
| `tracert -h 5 site.com` | تتبع المسار ولكن التوقف بعد فحص 5 قفزات كحد أقصى (حتى لو لم يتم الوصول للهدف). |
| `tracert -w 2000 8.8.8.8` | تتبع المسار مع انتظار رد كل قفزة لمدة ثانيتين (2000 مللي ثانية). |
| `tracert -6 target_ipv6` | إجبار الأمر على استخدام بروتوكول IPv6 لتتبع المسار. |

### سيناريوهات عملية (Practical Scenarios)

لدمج هذه الأدوات، اتبع الخطوات التالية عند شكوى موظف من "عدم وجود إنترنت":

**السيناريو 1: لا يوجد اتصال إطلاقاً**
1.  قم بتشغيل `ipconfig` للتأكد من أنك حصلت على عنوان IP صحيح (مثل 192.168.x.x) وليس رقم يبدأ بـ 169.254 (وهو يعني فشل الاتصال بالسيرفر).
2.  قم بـ `ping` عنوان الـ Gateway (البوابة) الخاص بك.
    *   إذا نجح الـ Ping: المشكلة ليست في الكابل أو التوجيه المحلي، المشكلة قد تكون في الـ Modem أو مزود الخدمة (ISP).
    *   إذا فشل الـ Ping: المشكلة في الشبكة المحلية (Local Network) أو الكابل.

**السيناريو 2: الإنترنت بطيء جداً**
1.  قم بـ `ping` لموقع معروف (مثل Google) مع استمرار الاتصال (`ping -t`).
2.  راقب نسبة (Packet Loss) والوقت (Latency).
3.  إذا كانت النسبة مرتفعة، قم بتشغيل `tracert` لمعرفة أي مرحلة (Hop) يحدث فيها التردد العالي (High Latency).

**السيناريو 3: لا يمكن الدخول لموقع معين (مثلاً موقع البنك)**
1.  قم بـ `ping` لاسم الموقع (مثلاً bank.com).
    *   إذا حصلنا على IP ونجح الـ Ping: الموقع يعمل، المشكلة قد تكون في المتصفح أو إعدادات الـ DNS.
    *   إذا فشل الـ Ping: الموقع مغلق أو محظور من مزود الخدمة.
2.  قم بـ `ping` لعنوان IP المباشر للموقع (إذا عرفته) للتأكد.
