# المحور الأول: مقدمة في واجهات برمجة التطبيقات (REST APIs)

### 1. التعريف والمفهوم الأساسي

في عالم أتمتة الشبكات (Network Automation)، ننتقل من الاعتماد الكلي على الواجهات النصية التقليدية (CLI - Command Line Interface) إلى الاعتماد على البروتوكولات والواجهات البرمجية.

**ما هي REST API؟**
تعرف اختصاراً بـ REST API (Representational State Transfer Application Programming Interface). هي مجموعة من القواعد والمبادئ التي تحكم كيفية تواصل التطبيقات مع بعضها البعض عبر الشبكة.

تُعد REST (Representational State Transfer) نمطاً معمارياً (Architectural Style) لتصميم خدمات الويب، وليس بروتوكولاً بحد ذاته. تعتمد هذه التقنية بشكل أساسي على بروتوكول النقل (HTTP - Hypertext Transfer Protocol) أو (HTTPS).

### 2. لماذا نستخدم REST APIs في الشبكات؟

في الماضي، كان مهندس الشبكات يقوم بتكوين الأجهزة (Configuration) يدوياً عبر (CLI). هذا الأسلوب يعاني من بطء التنفيذ وصعوبة تكرار العمليات على مئات الأجهزة.

أما مع استخدام (REST APIs)، يمكن لأداة أتمتة (Automation Tool) إرسال طلبات برمجية للحصول على معلومات من الموجه (Router) أو المبدل (Switch) أو تعديل إعداداته بسرعة ودقة عالية، مما يدعم مفاهيم الشبكات المعرفة بالبرمجيات (SDN - Software-Defined Networking).

### 3. المبادئ الأساسية لـ REST

لكي يُعتبر النظام "مبنيًا على مبادئ REST"، يجب أن يلتزم بعدة قواعد أساسية:

1.  **عميل-خادم (Client-Server Architecture):**
    هناك فصل واضح بين العميل (Client) الذي يطلب الخدمة، والخادم (Server) الذي يوفرها. هذا يسمح بتطوير كل جزء بشكل مستقل.

2.  **عديمة الحالة (Stateless):**
    هذا هو المبدأ الأهم. يعني أن كل طلب (Request) من العميل يجب أن يحتوي على جميع المعلومات اللازمة لمعالجته. الخادم لا يخزن حالة الجلسة (Session State) الخاصة بالعميل بين الطلبات. كل طلب يعتبر عملية منفصلة تماماً.

3.  **القابلية للتخزين المؤقت (Cacheability):**
    يجب أن يمكن تحديد الطلبات سواء كانت قابلة للتخزين المؤقت (Cachable) أم لا، لتحسين الأداء وتقليل الحمل على الشبكة.

4.  **الواجهة الموحدة (Uniform Interface):**
    يجب أن تكون الواجهة بين العميل والخادم موحدة وبسيطة. في سياق الشبكات، يتم تحقيق ذلك من خلال:
    *   استخدام (URI - Uniform Resource Identifier) لتحديد المورد (Resource) المستهدف.
    *   استخدام (HTTP Methods) لأداء العمليات على المورد.
    *   التعامل مع البيانات (Data Representation) بصيغة موحدة مثل (JSON).

### 4. الطرق (HTTP Methods) وتطبيقاتها في الشبكات

تستخدم الـ (REST APIs) أوامر (HTTP) لتنفيذ العمليات. أهم هذه الأوامر في سياق أتمتة الشبكات هي:

*   **GET (استرداد البيانات):**
    *   الوظيفة: قراءة المعلومات من الجهاز دون تغييرها.
    *   مثال: طلب معلومات عن حالة المنافذ (Interface Status) أو جدول التوجيه (Routing Table).
    *   استخدام: `GET /api/interface`

*   **POST (إنشاء بيانات):**
    *   الوظيفة: إرسال بيانات جديدة إلى الجهاز لإنشاء مورد (Resource) جديد.
    *   مثال: إنشاء قائمة وصول (Access Control List) جديدة.
    *   استخدام: `POST /api/acl`

*   **PUT / PATCH (تحديث البيانات):**
    *   الوظيفة: تحديث مورد موجود بالكامل (PUT) أو جزئياً (PATCH).
    *   مثال: تغيير اسم المنفذ (Interface Name) أو تحديث عنوان IP.
    *   استخدام: `PUT /api/interface/0/0/0`

*   **DELETE (حذف البيانات):**
    *   الوظيفة: حذف مورد موجود من الجهاز.
    *   مثال: حذف قاعدة توجيه (Routing Rule) معينة.
    *   استخدام: `DELETE /api/route/10.0.0.1`

### 5. صيغة البيانات (JSON)

عندما يرسل العميل طلباً (Request) أو يستقبل ردًا (Response) من الجهاز، يجب أن تكون البيانات مكتوبة بصيغة يفهمها كلا الطرفين.

أصبحت (JSON - JavaScript Object Notation) هي الصيغة القياسية في (REST APIs) بدلاً من (XML) القديم، وذلك للأسباب التالية:
*   خفيفة الوزن (Lightweight).
*   سهلة القراءة والكتابة للإنسان والآلة.
*   تدعم بناء الجمل (Nested structures) بشكل ممتاز لتنظيم بيانات الشبكات.

**مثال على بنية JSON:**
```json
{
  "interface": "GigabitEthernet0/0/0",
  "status": "up",
  "ip_address": "192.168.1.1",
  "subnet_mask": "255.255.255.0"
}
```

### 6. ملخص المحور

في هذا المحور، تعلمنا أن:
1.  الـ (REST APIs) هي المعيار الحديث لأتمتة الشبكات.
2.  تعتمد على بروتوكول (HTTP) وتعمل بنظام (Stateless).
3.  تستخدم (HTTP Methods) مثل (GET) و (POST) للتحكم في الأجهزة.
4.  تستخدم صيغة (JSON) لنقل البيانات بين العميل والخادم.

في المحور القادم سنتناول الفرق بين (RESTCONF) و (NETCONF) وكيفية التعامل مع (REST APIs) عملياً.
