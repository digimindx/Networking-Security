# أساسيات Microsoft Entra ID
**Microsoft Entra ID**
 (التي كانت تُعرف سابقاً بـ **Azure Active Directory** أو **Azure AD**) هي خدمة إدارة الهوية والوصول (Identity and Access Management - IAM) المقدمة من مايكروسوفت. تعمل هذه الخدمة كـ "بوابة" (Gateway) للتحكم في من يمكنه الدخول إلى الموارد، وكيفية الدخول إليها، ومتى يمكنه الدخول.

---

## 1. المفاهيم الأساسية (Core Concepts)

لفهم Microsoft Entra ID، يجب استيعاب المصطلحات والمكونات الرئيسية التالية:

### أ. المستأجر (Tenant)
المستأجر هو التمثيل المحدد لمؤسسة معينة داخل بيئة Microsoft Entra ID. كل مستأجر له معرف فريد (Unique Identifier) وعنوان URL خاص. عند إنشاء حساب Microsoft 365 أو Azure، يتم تلقائياً إنشاء مستأجر (Tenant) جديد لك. يعمل المستأجر كحيز عمل (Work Space) معزول لتخزين بيانات المستخدمين والتطبيقات.

### ب. المستخدمون (Users)
يمثلون الأشخاص الذين يحتاجون إلى تسجيل الدخول للوصول إلى الموارد. يمكن تصنيف المستخدمين إلى:
*   **مستخدمين مسجلين (Licensed Users):** لديهم حسابات كاملة.
*   **مستخدمين زوار (Guest Users):** يمكنهم الوصول إلى مواردك ولكنهم ينتمون إلى مستأجرين آخرين (مثلاً شركاء الأعمال).

### ج. المجموعات (Groups)
تُستخدم لتجميع المستخدمين أو الأجهزة أو التطبيقات لتسهيل إدارة الصلاحيات (Permissions Management). بدلاً من إعطاء الصلاحيات لمستخدم واحد، يتم إعطاؤها للمجموعة، وأي شخص ينضم إليها يرث الصلاحيات تلقائياً.

### د. كائنات التطبيقات (Application Objects)
تمثل التطبيقات التي يحتاج المستخدمون إلى استخدامها. عند تسجيل تطبيق في Microsoft Entra ID، يتم إنشاء كائن (Object) يمثل هذا التطبيق ويحدد كيفية تفاعله مع الهوية.

### هـ. المسؤولة الخدمية (Service Principal)
عند تسجيل تطبيق في Microsoft Entra ID، يتم إنشاء "مسؤول خدمي" (Service Principal). هو عبارة عن مثيل (Instance) للتطبيق داخل المستأجر (Tenant) الخاص بك، ويمنح التطبيق القدرة على تسجيل الدخول والوصول إلى الموارد ككيان مستقل.

## 2. الميزات والوظائف الرئيسية (Key Features)

تركز شهادة SC-900 على فهم كيفية استخدام Microsoft Entra ID لتعزيز الأمن:

### أ. تسجيل الدخول الموحد (Single Sign-On - SSO)
تسمح هذه الميزة للمستخدم بتسجيل الدخول مرة واحدة باستخدام حساب Microsoft Entra ID واحد للوصول إلى العديد من التطبيقات السحابية (مثل Office 365، Salesforce، Zoom) دون الحاجة لتكرار عملية المصادقة.

### ب. المصادقة متعددة العوامل (Multi-Factor Authentication - MFA)
تضيف طبقة أمان إضافية تتطلب من المستخدم تقديم أكثر من إثبات واحد (Evidence) لإثبات هويته. عادةً ما يكون ذلك عبر:
1.  كلمة المرور (Password).
2.  شيء يملكه المستخدم (مثل هاتفه لتلقي رمز OTP أو إشعار).
3.  شيء يتعلق به (مثل بصمة الإصبع أو الوجه).

### ج. الوصول المشروط (Conditional Access)
تعتبر هذه الميزة حجر الزاوية في استراتيجية "الصفر ثقة" (Zero Trust). تسمح لك بتطبيق سياسات (Policies) ديناميكية تعتمد على سياق الدخول، مثل:
*   **الموقع الجغرافي (Location):** رفض الدخول إذا كان المستخدم في دولة محظورة.
*   **جهاز المستخدم (Device):** السماح بالدخول فقط إذا كان الجهاز مسجلاً (Enrolled) ومتوافقاً.
*   **حالة الخطر (Risk Level):** طلب MFA إذا اكتشف النظام سلوك دخول مشبوه.

### د. حماية الهوية (Identity Protection)
خدمة تقوم بمراقبة النشاطات المشبوهة (مثل الدخول من عنوان IP غير معتاد) وتتخذ إجراءات تلقائية مثل قفل الحساب أو مطالبة المستخدم بتغيير كلمة المرور.

### هـ. إدارة الهويات المميزة (Privileged Identity Management - PIM)
تساعد في إدارة، ضبط، وإدارة وصول المستخدمين (بما فيهم المسؤولون) إلى الموارد الحرجة (مثل Azure Admin أو Entra ID Global Admin). تسمح بنظام "الدخول عند الطلب" (Just-in-Time Access) بدلاً من منح الصلاحيات الدائمة.

## 3. سيناريوهات الاستخدام (Use Cases)

### أ. الوصول إلى موارد Azure (Azure Resources)
يستخدم Microsoft Entra ID للتحكم في من يمكنه إدارة الخوادم، قواعد البيانات، والشبكات في بيئة Azure.

### ب. الوصول إلى التطبيقات SaaS (Software as a Service)
تعمل كـ Identity Provider (IdP) للتطبيقات الخارجية، مما يتيح للشركات استخدام حساباتها الداخلية للوصول لبرامج مثل Adobe Creative Cloud أو Slack.

### ج. الهوية الهجينة (Hybrid Identity)
تسمح بربط البنية التحتية المحلية (On-premises) مع السحابة عبر أدوات مثل:
*   **Microsoft Entra Connect:** لمزامنة المستخدمين من Active Directory المحلي إلى السحابة.
*   **Password Hash Sync (PHS):** مزامنة تجزئات كلمات المرور.
*   **Pass-through Authentication:** التحقق من كلمات المرور مباشرة من السيرفر المحلي.

## 4. الترخيص (Licensing)

تتوفر خدمات Microsoft Entra ID عبر طبقات ترخيص مختلفة:
1.  **Free:** الوظائف الأساسية (SSO، MFA الأساسي، Groups).
2.  **P1 (Premium P1):** يشمل الوصول المشروط (Conditional Access)، حماية الهوية (Identity Protection)، وإدارة الهويات المميزة (PIM).
3.  **P2 (Premium P2):** يشمل كل ما سبق بالإضافة إلى تحليلات متقدمة وإدارة متقدمة للمخاطر.

---

## 5. ملخص لنقاط الامتحان (SC-900 Key Takeaways)

*   Microsoft Entra ID هو بديل لـ Azure AD (تم تغيير الاسم ليعكس توسع الخدمة).
*   المسؤولون عن إدارة الهوية في Microsoft Cloud هم مسؤولو Microsoft Entra ID.
*   الفرق الجوهري بين "المستخدم" و "المسؤول الخدمي" (Service Principal) هو أن الأول بشري والثاني لتطبيقات وخدمات.
*   سياسة "الوصول المشروط" (Conditional Access) هي الأداة الأساسية لتطبيق سياسات الأمن الديناميكية.
*   لا يمكن فصل الهوية عن الأمن؛ فبدون إدارة هوية قوية، تكون الموارد السحابية عرضة للاختراق.
